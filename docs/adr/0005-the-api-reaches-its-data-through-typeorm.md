# The API reaches its data through TypeORM

`apps/api` leaves PostgREST for its data path: one long-lived TypeORM (1.x) `DataSource` over a direct Postgres connection, through Supabase's Supavisor session pooler. supabase-js stays only on the planes that are not data — Auth (JWKS verification, `auth.admin.deleteUser`) and Storage signed-upload tokens (ADR 0001) — plus the dev seed script. The schema's source of truth does not move: migrations remain the Supabase CLI's SQL under `apps/api/supabase/` (ADR 0003), entities are hand-written mirrors with `synchronize: false` forever, and drift is caught by the e2e suite running against the real schema. The code layers by feature module: controllers carry wire concerns only, services own business logic and the entity↔contract mapping through pure per-feature mappers, and every SQL statement lives in a repository private to its module — one repository per aggregate, cross-feature reads only through providers a module exports. The wire boundary stays the zod contracts: every response is parsed through its schema, which is what strips answer material off the wire.

The move buys what PostgREST structurally cannot give: transactions (the ADR 0004 finalize; attempt issuance loses its insert-then-reread unique-violation dance), schema-typed queries in place of one hand-aliased select string per endpoint, and a repository layer with real seams. We rejected keeping supabase-js under repositories (no transactions, hand-typed rows), class-transformer for serialization (no release since 2021, and it would duplicate every contract as entity decorators while dropping the zod parse), and the introspection-first tools — Prisma's client generation breaks the source-first `check` that never builds, Drizzle sits outside the NestJS docs and below a stable 1.0 — where TypeORM carries first-class Nest integration and shipped 1.0 in 2026.

## Consequences

- Entities mirror the SQL by hand: a new table costs a migration, an entity, and nothing else — the snake_case→camelCase aliasing moves from select strings into `@Column({ name })` definitions.
- The direct connection authenticates as the migrations' table owner, so the API stops depending on `service_role` grants for its own path; ADR 0003's three locks keep denying every other door, PostgREST included.
- `get_random_questions` stops being an RPC and becomes repository SQL.
- `DATABASE_URL` joins `env.ts`; local dev and e2e point it at `supabase start`'s local Postgres.
- The "one aliased select string per endpoint, no ORM" rule leaves `AGENTS.md` with the refactor that lands this decision.
