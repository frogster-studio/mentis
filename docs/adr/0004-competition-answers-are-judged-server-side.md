# Competition answers are judged server-side

The API issues every competition Attempt: it draws the Theme and 10 Questions per Player (excluding every Theme among the Player's previous two Competition Days and earlier Attempts today), remembers what it served, and returns the Questions with pre-shuffled Carré choices but no Canonical Answer, Aliases or Misspellings. The phone plays the whole session offline-tolerant — the same local 25 s Countdown, one-way Carré switch and end-of-session reveal as practice — then pushes one idempotent finalize batch of raw answers (typed text or chosen choice, self-reported mode, client-claimed elapsed) through the outbox. The API judges each answer with the same shared `matchAnswer` practice runs on-device, verifies it targets a served Question, prices 5/2/0 by mode, zero-fills what never resolved, and stores the full transcript (`competition_attempts` + `competition_answers`, `matched_via` included). A Competition Day is the Europe/Paris date at issuance; kinds initial/Replay/Catch-up are `unique(owner, day, kind)`; a day scores its best Attempt, ≤ 50 by construction; the Season Total is materialized per Account at finalize ([ADR 0009](0009-season-standings-are-materialized-per-account-at-finalize.md)). Quitting finalizes the rest at 0 and consumes the Attempt; a silent Attempt is lazily zero-finalized once the Competition Day it was issued on has passed (a Catch-up is issued the day after the one it fills); an active one resumes with its original Questions, answers blank. Replay and Catch-up are issued to a Premium Account alone — the local mirror compare of [ADR 0006](0006-premium-truth-is-mirrored-from-revenuecat.md), checked at issuance and never again, so a subscription lapsing mid-session voids nothing.

We rejected per-question server pacing (a round trip between Questions and mandatory connectivity for a whole session — subway play — buying a time-box that never stopped a second device), signed transcripts (a key in a public client is extractable), one shared daily quiz for all Players (shared content leaks socially; per-Player difficulty variance washes out over a month-long season), and duplicating the matcher in the API (the rules would fork).

## Consequences

- The threat model is explicit: forged scores, extracted answers and extra Attempts are dead; a modded client — or a second device dictating Questions to an AI — has unlimited thinking time and can reach 50/day. Accepted. The stored stamps make anomaly review possible later without new capture.
- Carré choices ship at issuance so the one-way switch works offline; mode is therefore self-reported, and Carré knowledge can be laundered into Cash pricing — dominated by the accepted lookup risk.
- `matchAnswer` and `squareChoices` leave `apps/mobile` for `@mentis/answer-matching`, a zero-dependency workspace package beside `@mentis/contracts` outside the ten-dependency cap; the API pre-shuffles competition choices server-side.
- Practice is untouched: on-device matching ([mobile ADR 0001](../../apps/mobile/docs/adr/0001-deterministic-answer-matching.md)), the trusted-integer session sync ([mobile ADR 0003](../../apps/mobile/docs/adr/0003-append-only-session-sync.md)), and the public answers-included draw stay; competition never writes `quiz_sessions`, so personal stats remain practice-only.
