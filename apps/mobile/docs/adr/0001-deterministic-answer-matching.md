# Deterministic on-device answer matching (no runtime AI)

A Cash answer must be judged correct despite case, accents, articles, typos and alternate forms. We considered runtime LLM judging (best "human feeling", but network-dependent, non-deterministic, costly, needs a protected edge function) and rejected it for v1. Instead, matching is a pure TS pipeline running on-device: normalization (lowercase, accent-folding, punctuation/article stripping) → exact match against the Canonical Answer, curated Aliases and pre-generated Misspellings → bounded Levenshtein tolerance against the Canonical Answer and Aliases only (never against Misspellings, never on numbers). AI is used only offline, at content-authoring time, to propose Aliases and Misspellings. This keeps scoring instant, offline-capable, reproducible and unit-testable; the cost is a curation burden per question and a ceiling on semantic flexibility (a v2 may add batched LLM fallback at session end, since answers are only revealed there).
