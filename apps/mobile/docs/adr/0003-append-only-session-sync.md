# Append-only session sync with prompted device→account transfer

When a signed-in Player finishes a Quiz Session, the client records it locally first (home updates instantly, offline included), queues it in a small persisted outbox, and pushes it to the API gateway as one session keyed by a client-generated UUID — the server inserts if absent, so retries and re-sends are no-op successes, two offline devices can never conflict because nothing but appends exist, and Account Stats are always derived, never stored. Pre-auth Device Stats (per-Theme aggregates, the only shape the device holds) enter an Account through a one-time consented Stats Transfer at sign-in: a move keyed per device (baseline rows, idempotent), not a copy, so declining leaves them dormant on the device and a second account signing in on the same phone can never absorb another person's play. We rejected mirroring aggregates via increment RPCs (retry-safety forces per-session dedup keys anyway — reinventing session ids without keeping the sessions the social era needs) and last-write-wins snapshots (cross-device play silently destroys data). Consequence: player tables must not cascade-delete from content tables — hosted Themes can be replaced over time — so sessions capture the Theme name at record time, exactly as the local store already does.
