# Mentis monorepo

Three apps sharing one Supabase project. **bun only** — never npm, pnpm, or yarn (`bun install`, `bun run`, `bunx`).

```
apps/admin/               # Next.js back-office (Vercel). App details: apps/admin/AGENTS.md
apps/api/                 # NestJS REST gateway (Railway later) + the SHARED schema. App details: apps/api/AGENTS.md
apps/mobile/              # Expo quiz app (EAS later). App details: apps/mobile/AGENTS.md
packages/answer-matching/ # @mentis/answer-matching — the Cash judge + Carré shuffle, phone and API
packages/contracts/       # @mentis/contracts — zod request/response schemas the API publishes
```

Before working inside an app, read its `AGENTS.md`. The repo has two bounded contexts, mapped in [CONTEXT-MAP.md](CONTEXT-MAP.md) — Quiz play ([apps/mobile/CONTEXT.md](apps/mobile/CONTEXT.md)) and Catalog curation ([apps/admin/CONTEXT.md](apps/admin/CONTEXT.md)); the API deliberately has none — it publishes those vocabularies rather than owning one.

Instructions live in `AGENTS.md` alone; every `CLAUDE.md` here is a one-line `@AGENTS.md` import, so each rule is written once and every agent reads it.

## Commands (repo root)

- `bun run format` — Biome auto-fix, whole repo
- `bun run knip` — drop unused files/exports/deps, then format
- `bun run typecheck` / `bun run test` — every workspace
- `bun run check` — all of the above; **every piece of work must end with `check` green**
- Single workspace: `bun run --filter @mentis/admin <script>` (also `@mentis/api`, `@mentis/mobile`, `@mentis/contracts`, `@mentis/answer-matching`)

Biome and Knip are configured **only at the root** (`biome.json`, `knip.json`) — never add per-app configs or per-app lint scripts. Style: double quotes, 2-space indent, line width 100.

## Database

Migrations live in `apps/api/src/_database/migrations/`, generated by the TypeORM CLI from the entities beside them — the gateway owns the schema. `apps/api` is the sole database gateway: admin and mobile both reach the data through it, and neither holds a database key. Mobile still uses `@supabase/supabase-js` for **auth only** (sign-in, session, token refresh). The migrations are generated output — `migration:generate` is Hugo's command, never an agent's. What no entity expresses stays out of the repo: the schema is born locked by SQL run on the dashboard — RLS on every table, zero policies, privileges for `service_role` alone ([ADR 0003](docs/adr/0003-database-admits-only-the-api.md)).
