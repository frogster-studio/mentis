## Item 7 — the shared legal links module (mobile) — DONE

Done: src/lib/legal-links.ts + its spec, src/lib/open-external-link.ts, legal-line.tsx rewired, LEGAL_URL gone.
Decisions:
- **Split into two modules, against the PRD's "one shared module"** — and the PRD Decisions now say so. `openExternalLink` needs `expo-web-browser`, whose `expo-modules-core` import dies in vitest's node environment (`__DEV__ is not defined`, then `Cannot read properties of undefined (reading 'EventEmitter')` — it wants the native Expo global). Anything importing the URLs would have dragged that in, so the spec the PRD asks for could not exist. legal-links.ts is now import-free; open-external-link.ts holds the opener.
- Probed the alternative first: aliasing `react-native` -> `react-native-web` in vitest.config.mts + `define: { __DEV__: "true" }`. react-native then loads, expo-web-browser still does not. Reverted — stubbing the Expo global to assert three string literals is test infrastructure bought at a bad price, and the alias would silently pin `Platform.OS` to "web" for every future spec. Item 8's store-name function is a pure function of "ios" | "android" precisely so it never needs Platform in a test.
- The three URLs are built from one `SITE_URL` const, so the domain is written once; the spec still asserts the full literal strings, so a wrong base fails.
- `openExternalLink(url)` is the old `openLegal` with the URL as a parameter — same web/native branch, same comment. The `suppressHighlighting` comment stayed on the links.
- Arrow wrappers at the call sites (`onPress={() => openExternalLink(PRIVACY_URL)}`) rather than two named local functions: the sentence now opens two different pages, and a wrapper per link reads shorter than a helper per link.
- SUPPORT_URL is exported but unused until item 9. Knip stays green because the vitest plugin treats *.test.ts as entries and the spec imports all three.
