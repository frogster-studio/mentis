- Contract: `authoredExplanation` is `z.string().nullable().transform((e) => e?.trim() || null).refine(...)`. The `|| null` collapses empty *and* whitespace-only into null in one step, and the refine runs after the transform so the 400 cap counts trimmed characters, as the PRD asked. - No API code changed at all. The service spreads the contract's shape into `DeepPartial<QuestionEntity>`, so the Explanation rides along; `stageQuestion` sends `{ id, readyToBePublished }` only, and TypeORM `preload` skips `undefined` while applying `null`, so staging leaves the Explanation untouched and a full PATCH with null clears it. - The app contract is untouched and zod strips by default, so `/app/*` never serves the Explanation — no test or comment states that, per the PRD's out-of-scope rule.

## PRD Item 2 — the Explanation textarea and its 400-character counter — DONE

- Typing is never blocked: no `maxLength` on the textarea. The Editor sees how far over they are and cuts the text down themselves.
